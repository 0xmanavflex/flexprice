# @fp/ui changelog

Every material change to the shared UI — look, API, or provenance — gets a line
the commit it lands, so component drift is visible from the start rather than
reconstructed at the end. See `docs/component-guardrails.md` for the policy.

Format: `- <date> — <area>: <what changed> (<why / provenance>)`.

## 2026-09-29

From a live-data UI audit run against production at five viewports (1920 / 1440
/ 1280 / 768 / 390). Findings and measurements in `docs/audit/`.

- 2026-09-29 — flexprice/EntityList + flexprice/cells: **new, and the one list table every list screen is to be built on.** `EntityList` is a composition over `@reui/data-grid` (+ `@reui/filters` for the filter chip row and `@reui/empty-state-3` for the first-run illustration); `cells.tsx` holds the column helpers (`textColumn`, `idColumn`, `dateColumn`, `moneyColumn`, `numberColumn`, `pillColumn`) and the one 24px dot pill. **`FeatureGrid` is migrated onto it as the reference; the other eleven grids still carry their own hand-built `DataGrid` and are unchanged.** The layout is deliberately **not** a prop — there is no `tableLayout`, `tableClassNames` or raw `ColumnDef` passthrough, because every one of those is how the twelve grids drifted apart in the first place. Fixed here, once: borderless (no outer box, full content width), a 44px `bg-muted/60` header band with rounded ends and no rule beneath it, 60px rows with 16px side padding on one line, `border-border/40` separators with none under the last row, headers uppercase/11px/wide-tracked/muted, and everything left-aligned — amounts included, with `tabular-nums`. Weight is capped at medium throughout. Footer is `DataGridPagination` at 10/25/50/100.
- 2026-09-29 — flexprice/EntityList — **column width and pinning are measured, not configured.** A `ResizeObserver` on the frame (never on the table — measuring the thing you are about to resize is a feedback loop) scales every non-`fixed` column so the set spans the content width exactly; the rounding remainder goes to the widest column, because a 1px shortfall shows as a pale stripe down the header band. Going the other way the scale floors at **0.94** — six per cent of squeeze — after which the table scrolls sideways instead. That one number also decides pinning: the checkbox (44px) and `⋯` (40px) columns pin, with the registry's `data-last-col` divider, **only when the table actually overflows**, so a table that fits draws no divider around a column that is not going anywhere. Sticky header is **off**: the page scrolls, and a table that owns its own height ends up with a second scrollbar beside the page's.
- 2026-09-29 — flexprice/EntityList — **TanStack v9 renamed the column-pinning axis to `{ start, end }`.** A `{ left, right }` object still type-checks against the state slot and then reads as *no pinning at all*: `table_getHeaderGroups` asks for `start.length`, gets `undefined`, and the grid throws inside `DataGridScrollArea`. v9 also stopped exporting `VisibilityState`; it is `Record<string, boolean>`. Both cost a full test run to find.
- 2026-09-29 — flexprice/EntityList — **every Base UI menu part must sit inside a `DropdownMenuGroup`.** A bare `DropdownMenuLabel` / `DropdownMenuCheckboxItem` / `DropdownMenuItem` under `DropdownMenuContent` throws `MenuGroupContext is missing` and takes the whole menu down rather than degrading. The `⋯` toolbar menu (column show/hide + Export CSV) and the per-row `⋯` menu both group their sections.
- 2026-09-29 — flexprice/EntityList — the toolbar: 288px search left; a shadcn `Select` for status **with a count per option**, replacing the row of view tabs (a count is optional and only ever the server's `pagination.total` — a screen that cannot get one honestly shows no number rather than counting the 25 rows it happens to hold); Filter and Sort as 32px icon buttons carrying a small `--primary` count badge; a `⋯` menu for column visibility and Export CSV; and the primary CTA last. Export writes the **visible** columns from each helper's `text()`, BOM-prefixed so Excel reads it as UTF-8.
- 2026-09-29 — compositions/FilterBar, compositions/SortMenu: **additive optional `trigger` prop on both.** Defaults are byte-identical to before, so the eleven unmigrated grids are unaffected; `EntityList` passes an icon-only trigger with a count badge, because a bar that draws its own "Filter" button beside a list that also wants one gives you two Filter buttons. `FilterBar`'s draft-holding behaviour and its `variant="basic"` default are untouched.
- 2026-09-29 — flexprice/FeatureGrid: migrated onto `EntityList`; the file is now columns, row actions and a query translation. **Breaking:** the `filters` ReactNode prop is gone (the filter builder is the shared toolbar's now) and `statusCounts` is added; `FeatureListPage` is updated and is the only call site. Status moved out of the filter builder into the toolbar dropdown — offering it in both gives two controls writing `query.statuses`, which disagree immediately. `FeatureFilters` is now unused by the features page.
- 2026-09-29 — components/blocks/empty-state-3: installed (Pro). Only `ProjectsEmptyIllustration` is used — the block's own copy, buttons and template grid are its demo. `styles.css` verified byte-identical before and after; the four primitives `--overwrite` rewrote (`button`, `empty`, `item`, `separator`) were restored, their only diff being the dropped `@ts-nocheck` header (and `separator`'s `"use client"`).
- 2026-09-29 — flexprice/QuotaCard: new. One entitled feature's quota as a card, composed over `@reui/stats-11` — whose "API Call Quota" layout is already the six readings a customer's entitlement has (used + charged amount on one row, a bar under them, remaining beside included, the renewal date in a divided footer). Provenance is **composition**, not `reui`: the block exports a propless component bound to its own `./data`, so the arrangement is reused and every figure arrives as a prop. Three forced deviations — `included: null` is **unlimited**, so no denominator, no percentage and **no bar** (a full bar reads "exhausted", an empty one "unused", and both are claims the data does not make; a `?? 0` would print "0 of 0" for the most generous grant there is); the block's green "3000 free calls left" is a `success-light` Badge, because `text-success` at that size measures 2.95:1; and the cost slot renders `—` with its reason, since nothing in the API prices a per-feature overage and `money.ts` forbids computing one. The bar takes `series-1` normally and the `critical` status token over quota — a `ChartTone` via `toneColor`, never a colour from the call site.
- 2026-09-29 — flexprice/QuotaCard — **of the six readings the design asks for, four are real, one is derived from two real ones, and one does not exist.** Real, straight off `GET /customers/usage`: used quantity (`current_usage`), included quantity (`total_limit`, null = unlimited), percent used (`usage_percent` — taken from the API rather than divided here, so the card and the server cannot disagree about rounding) and the reset date (`next_usage_reset_at`). Derived: remaining, as `total_limit − current_usage`, two counts from the same response. Absent: **overage**. `FeatureUsageSummary` carries `is_soft_limit` but no overage figure, and the only overage anywhere in the SDK is the monetary commitment overage on `GET /subscriptions/usage`, keyed by meter and line item rather than by entitlement — a different concept, not a substitute. Units are absent too: the wire sends `unit_plural` but `TenantFeatureUsage` does not keep it, so the readings are bare counts rather than invented nouns. `OverageStaysADash` in the story is the regression guard.
- 2026-09-29 — flexprice/CustomerDetail: the Usage tab takes an optional `usage` ReactNode slot, rendering the customer's `QuotaCard` grid in place of the "No usage to show yet" empty state. A slot rather than a data prop because the quota read is its own endpoint with its own loading and failure states, and this component does not fetch; omitted, the section behaves exactly as before.
- 2026-09-29 — flexprice/charts: **new shared chart library** for the Overview and Revenue dashboards — `MetricChart` and `BlurredEmpty` in `charts.tsx`, plus `PillColumns` (`@reui/stats-14`), `HalfDonut` (`@reui/chart-12`), `SegmentMeter` (`@reui/chart-14`), `SplitMeter` (`@reui/chart-14` extended to several tones in one track) and `ArcGauge` (`@reui/chart-7`). `MetricChart` is **not** from a block: shadcn `Chart` (Recharts) under a stat-tab strip, after the Vercel console. The five block-derived ones are **composition, not `reui`** — each block exports a propless `Chart()` bound to its own `./data`, so they are adapted for their mark and geometry over real data, never mounted. `stats-14`, `chart-14` and `chart-7` installed under `components/blocks/**`; `styles.css` verified byte-identical across all three installs, and the primitives `--overwrite` rewrote (`avatar`, `tabs`, `button`, `card`, `tooltip`, `dropdown-menu`, `frame`) were restored — their only diff was a shuffled `"use client"`.
- 2026-09-29 — flexprice/charts — **no component in the library takes a colour.** They take a `ChartTone`, a closed union mapped to `--chart-1..5` and the status tokens in exactly one place, so a call site cannot express an unvalidated colour and the derived palette cannot drift. `series-1..5` are categorical, handed out in fixed order and **clamped rather than cycled** — cycling would give series 1 and 6 the same colour, which reads as "these are the same thing". `good`/`warning`/`critical` are reserved for state (`HalfDonut`'s paid/open/overdue, `ArcGauge`'s health) and are never in the categorical rotation. Trend deltas are `TrendBadge` (`success-light`/`destructive-light`), not coloured text — a tripwire story confirmed the a11y gate still fails `text-success` at 12px (3.67:1 light, threshold 4.5).
- 2026-09-29 — flexprice/charts: all seven are **presentational and fully controlled** — no fetching, and no `useState` for anything a page owns, so `MetricChart`'s active tab can live in the URL. Every multi-series mark carries a legend, so identity is never on colour alone; every mark carries a hover layer (a dashed crosshair on the line, a per-mark tooltip on the columns, arcs and meter tracks) whose triggers are **focusable buttons** carrying the exact reading as their accessible name, so the figure behind the approximation is reachable without a mouse. `BlurredEmpty`'s decorative chart is `aria-hidden` + `inert` + `pointer-events-none` — all three, since `aria-hidden` alone leaves a tabbable control a screen reader then refuses to describe. Optional props are typed `?: T | undefined` so pages can pass conditional values under `exactOptionalPropertyTypes`.
- 2026-09-29 — flexprice/DashboardHome: **rewritten, and its provenance is now composition over five ReUI blocks** — `@reui/chart-16` (filter row, divided stat strip, area chart), `@reui/chart-29` (stacked per-day bars), `@reui/chart-12` (half-donut gauge + footer breakdown), `@reui/chart-25` (sparkline rows), `@reui/chart-8` (ticked radial arc). All five are installed under `components/blocks/**` and **adapted, not mounted**: each hard-wires its own demo data and exposes no props, so the surface reuses their structure and chart geometry over real data. Rendered on Card, the project's declared `SURFACE`, though four of the blocks ship on Frame — the blocks were chosen for their charts, not their chrome. The component is now **presentational**: it takes resolved panel data, which is what lets its story exercise populated / first-run / unavailable as first-class states. Replaces a surface that carried its own sample numbers, which a live-data audit flagged as a blocker.
- 2026-09-29 — flexprice/DashboardHome — **the rule the rewrite is built to**: every number is API-sourced or absent, with no third category. Processing lag, request volume, p95 latency and error counts have no endpoint anywhere — not in `@fp/query`, not in `@fp/api`, not in the SDK, which exposes per-event debugging but no aggregate — so they render as `—` with the reason stated, following `SettingsUnavailable` and `ShellSearch`. The design's "+ Add filter" control is omitted rather than drawn dead for the same reason. `UnavailableMetricsStayAbsent` in the story is the regression guard: it asserts exactly four dashes and no invented figures.
- 2026-09-29 — flexprice/DashboardHome: trend deltas use `success-light` / `destructive-light` Badges, not coloured text. `text-success` is a background-tuned green measuring 2.95:1 as a foreground at 12px and failed the story's a11y gate — the same wall `Metric` hit and documented. Note also that the known `text-foreground/60` → `/70` fix does **not** generalise to `text-muted-foreground`: `/70` on it measures 2.95:1, because the repo's muted palette is already tuned at full opacity. Any alpha on it is what breaks contrast; all muted text here is plain `text-muted-foreground`.
- 2026-09-29 — flexprice/SettingsShell: new. Two-level settings navigation — a vertical section rail (`@reui/settings-7`) over a horizontal `variant="line"` strip (`@reui/settings-11`). Provenance is **composition**, not `reui`: it reproduces both blocks rather than importing them (each is a demo bound to its own `data.ts`) and deviates on breakpoint, scroll/fade, truncation, focus ring and tab contrast.
- 2026-09-29 — primitives/tabs — **KNOWN BUG, not fixed**: the vendored wrapper destructures `orientation` to write `data-orientation` and never forwards it to Base UI. Base UI's `TabsList` is what derives `aria-orientation` and feeds its composite key handler, so **every vertical `Tabs` in this repo is horizontal to assistive tech and answers Left/Right instead of Up/Down**, however it is drawn. `SettingsShell` reproduces the root locally to work around it; the registry file is untouched because vendored code is not hand-edited. Worth reporting upstream.
- 2026-09-29 — tooling: `src/hooks/**` added to the vendored lists in BOTH `packages/ui/scripts/vendor-suppress.mjs` and `packages/eslint-config/src/index.js`. They had drifted — the directory was in neither, so installing a block that pulled in `use-file-upload` broke typecheck, and adding it to only the suppress list then broke lint on the very `@ts-nocheck` that fixed it. The two lists must stay in step.
- 2026-09-29 — primitives/sheet: `side="right"` width ladder adapted — `w-full` below `sm`, then `sm:max-w-md lg:max-w-xl 2xl:max-w-2xl` (was `w-3/4` capped at `max-w-sm`). Stock was wrong at both ends: 292px on a 390 phone behind a dead 98px strip, and a fixed 384px on desktop — 20% of a 1920 screen for the multi-field plan and coupon editors. **This is a hand-edit of a vendored file, against `component-guardrails.md` §2**: the house-rule route (`styles.css` `data-slot`) cannot win here, because `@layer components` loses to the stock `data-[side=right]:sm:max-w-sm` utility. Declared, not discovered — the file carries an `ADAPTED` header, and a `pnpm ui:add sheet --overwrite` will silently revert it.
- 2026-09-29 — compositions/DetailShell: the tab strip scrolls (`overflow-x: auto` + scroll-snap + a `max-sm` edge fade) instead of clipping. At 390 the last tab — Information, the only place a plan's ID and description live — painted outside the strip and was unreachable by touch. Also raised inactive tab text from `text-foreground/60` (4.14:1, below the 4.5:1 floor) to `/70` (5.65:1) in light mode.
- 2026-09-29 — compositions/MetricRail: renders `null` when every tile is empty or zero. Add-on detail was showing Charges `0` / Starts at `—` / Currency `—` / Entitlements `0` — four tiles of nothing eating ~310px of the first screen on a phone — which the rail's own rule already forbade.
- 2026-09-29 — compositions/shell: mobile-sheet breakpoint `md` → `lg`. At exactly 768 the hamburger was `md:hidden` while the 260px push sidebar was still mounted, so a tablet had neither affordance and lost 34% of its width. Moved in all four places (sidebar primitive, `SidebarTrigger`, `SidebarInset`, rail handle) — a half-move is the bug.
- 2026-09-29 — compositions/shell/ShellBreadcrumb: crumb labels `truncate whitespace-nowrap`; a crumb that hides its label now hides its separator too (orphan `› ›` at 390); crumbs carrying content get `min-w-20` so the environment name wins the shrink race — it was truncating to "Sa…" on a billing console.
- 2026-09-29 — compositions/shell/ShellSearch: with no `onSearch`, the dialog states that search is unavailable and binds **no** shortcuts, instead of offering an input that silently discarded the query. API unchanged when `onSearch` is supplied.
- 2026-09-29 — compositions/shell/ShellNav, ShellAccount, ShellRailHandle: the mobile drawer closes on navigation; the account menu stops printing the same email twice; the rail handle gains a visible focus ring and returns `null` on mobile (its subtree was painting a stray 2×16 tick over the content card on every page).
- 2026-09-29 — compositions/GridToolbar, States, EmptyState: search no longer collapses to 53px at 390 (the row wraps below `sm` and search carries a floor); the first-run empty state keeps the toolbar mounted rather than replacing the whole surface; empty blocks centre in the available height instead of pinning to the top.
- 2026-09-29 — flexprice/InvoiceGrid, PaymentGrid: the invoice number truncates like `Money` does. With no invoice number the API returns `""`, so the cell fell back to a 30-char ULID and painted over the customer name — measured 136px of overrun at 1280.
- 2026-09-29 — flexprice/InvoiceFilters: new. Status facet for the invoice list, which had none. Offers only `STORED_INVOICE_STATUSES` — `Paid` and `Overdue` are derived by `deriveInvoiceStatus`, so filtering by them sent no status at all and returned every invoice under a chip claiming otherwise.
- 2026-09-29 — flexprice/ChargeTable: `emptyDescription` is a prop. The default copy said "**A plan** bills nothing until it has a charge" on the add-on page, and instructed the reader to add a charge on a surface with no add flow.
