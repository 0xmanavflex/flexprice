# @fp/ui changelog

Every material change to the shared UI — look, API, or provenance — gets a line
the commit it lands, so component drift is visible from the start rather than
reconstructed at the end. See `docs/component-guardrails.md` for the policy.

Format: `- <date> — <area>: <what changed> (<why / provenance>)`.

## 2026-10-06

- 2026-10-06 — compositions/FormToolbar + FormPage + WorkflowStepper: **the stepper now sits in the toolbar row.** `FormToolbar` takes a `center` slot, drawn between the title and Cancel/CTA (its own row below on phones); `FormPage` puts the c-stepper-1 numbered dots there instead of in a band under the toolbar. The current step's title is no longer drawn — it is announced to assistive tech only.
- 2026-10-06 — compositions/FormCard: **one form-9 card per form.** The main content of a form is now a single `FormCard` — header (title, description, Required/Optional badge), dashed inset rule, then rows with the title and its *visible* description on the left and the control on the right (17rem label column), as in `blocks/form-9`. The stacked small cards are gone: Customer, Add-on, Cost sheet, Coupon, Feature, Group and Price unit are each one card (Feature's type is now a row inside it); stepper forms (Subscription, Plan) show one card per step. `FormCard` accepts fragments of rows, and hints are shown under the title rather than behind an info icon. Recorded in `docs/design-changes/2026-10-06-form-preview-stepper.md`.
- 2026-10-06 — compositions/FormPage + FormPreview + WorkflowStepper (header variant): **one form shell with an optional stepper and an optional preview.** `FormPage` (toolbar mode) now takes `stepper={{ flow, label?, hideNav? }}` — the `useFormSteps` flow drawn in the header, c-stepper-1 style (numbered dots and separators, current step captioned), with Previous/Next in a new `StepNav` at the foot — and `preview` — the solution-billing-8 rail, built from the new `FormPreview` / `PreviewAmount` / `PreviewSection` / `PreviewRows` / `PreviewRow`. Pass neither for a plain centred form. `FormToolbar` gains `hideSubmit` (a staged form submits only from its last step). Vendored with the block set: `form-9`, `solution-billing-8`, `c-stepper-1`, `c-stepper-2` (+ `reui/tree`, `@headless-tree/*`); their demo internals are private, so the compositions rebuild the same markup and tokens, fed by props (lineage in each provenance note). **Every form is now on the toolbar:** Customer, Add-on, Cost sheet, Coupon (create + edit), Feature, Price unit, Payment, Credit note, Tax rate, Subscription, Plan; the eight preview cards render through `FormPreview`. `FormActions` is no longer used by any page. Recorded in `docs/design-changes/2026-10-06-form-preview-stepper.md`.
- 2026-10-06 — compositions/FormToolbar: **new.** The form-3 toolbar structure (close, divider, title, Cancel, primary CTA wired by `formId`) as a composition, because the vendored block is hard-wired to an invoice. `FormPage` takes it through a new `toolbar` prop (mutually exclusive with `footer`) and drops the outer Section in that mode; `FormCard` gains an optional Required/Optional `status` badge. Migrated: Customer, Add-on, Cost sheet, Group. Layout deviation from the reference `Composer` is recorded in `docs/design-changes/2026-10-06-form-toolbar.md`.

- 2026-09-29 — flexprice/EntityList + flexprice/cells: **new, and the one list table every list screen is to be built on.** `EntityList` is a composition over `@reui/data-grid` (+ `@reui/filters` for the filter chip row and `@reui/empty-state-3` for the first-run illustration); `cells.tsx` holds the column helpers (`textColumn`, `idColumn`, `dateColumn`, `moneyColumn`, `numberColumn`, `pillColumn`) and the one 24px dot pill. **`FeatureGrid` is migrated onto it as the reference; the other eleven grids still carry their own hand-built `DataGrid` and are unchanged.** The layout is deliberately **not** a prop — there is no `tableLayout`, `tableClassNames` or raw `ColumnDef` passthrough, because every one of those is how the twelve grids drifted apart in the first place. Fixed here, once: borderless (no outer box, full content width), a 44px `bg-muted/60` header band with rounded ends and no rule beneath it, 60px rows with 16px side padding on one line, `border-border/40` separators with none under the last row, headers uppercase/11px/wide-tracked/muted, and everything left-aligned — amounts included, with `tabular-nums`. Weight is capped at medium throughout. Footer is `DataGridPagination` at 10/25/50/100.
- 2026-09-29 — flexprice/EntityList — **column width and pinning are measured, not configured.** A `ResizeObserver` on the frame (never on the table — measuring the thing you are about to resize is a feedback loop) scales every non-`fixed` column so the set spans the content width exactly; the rounding remainder goes to the widest column, because a 1px shortfall shows as a pale stripe down the header band. Going the other way the scale floors at **0.94** — six per cent of squeeze — after which the table scrolls sideways instead. That one number also decides pinning: the checkbox (44px) and `⋯` (40px) columns pin, with the registry's `data-last-col` divider, **only when the table actually overflows**, so a table that fits draws no divider around a column that is not going anywhere. Sticky header is **off**: the page scrolls, and a table that owns its own height ends up with a second scrollbar beside the page's.
- 2026-09-29 — flexprice/EntityList — **TanStack v9 renamed the column-pinning axis to `{ start, end }`.** A `{ left, right }` object still type-checks against the state slot and then reads as *no pinning at all*: `table_getHeaderGroups` asks for `start.length`, gets `undefined`, and the grid throws inside `DataGridScrollArea`. v9 also stopped exporting `VisibilityState`; it is `Record<string, boolean>`. Both cost a full test run to find.
- 2026-09-29 — flexprice/EntityList — **every Base UI menu part must sit inside a `DropdownMenuGroup`.** A bare `DropdownMenuLabel` / `DropdownMenuCheckboxItem` / `DropdownMenuItem` under `DropdownMenuContent` throws `MenuGroupContext is missing` and takes the whole menu down rather than degrading. The `⋯` toolbar menu (column show/hide + Export CSV) and the per-row `⋯` menu both group their sections.
- 2026-09-29 — flexprice/EntityList — the toolbar: 288px search left; a shadcn `Select` for status **with a count per option**, replacing the row of view tabs (a count is optional and only ever the server's `pagination.total` — a screen that cannot get one honestly shows no number rather than counting the 25 rows it happens to hold); Filter and Sort as 32px icon buttons carrying a small `--primary` count badge; a `⋯` menu for column visibility and Export CSV; and the primary CTA last. - 2026-09-29 — flexprice/QuotaCard: new. One entitled feature's quota as a card, composed over `@reui/stats-11` — whose "API Call Quota" layout is already the six readings a customer's entitlement has (used + charged amount on one row, a bar under them, remaining beside included, the renewal date in a divided footer). Provenance is **composition**, not `reui`: the block exports a propless component bound to its own `./data`, so the arrangement is reused and every figure arrives as a prop. Three forced deviations — `included: null` is **unlimited**, so no denominator, no percentage and **no bar** (a full bar reads "exhausted", an empty one "unused", and both are claims the data does not make; a `?? 0` would print "0 of 0" for the most generous grant there is); the block's green "3000 free calls left" is a `success-light` Badge, because `text-success` at that size measures 2.95:1; and the cost slot renders `—` with its reason, since nothing in the API prices a per-feature overage and `money.ts` forbids computing one. The bar takes `series-1` normally and the `critical` status token over quota — a `ChartTone` via `toneColor`, never a colour from the call site.
- 2026-09-29 — flexprice/QuotaCard — **of the six readings the design asks for, four are real, one is derived from two real ones, and one does not exist.** Real, straight off `GET /customers/usage`: used quantity (`current_usage`), included quantity (`total_limit`, null = unlimited), percent used (`usage_percent` — taken from the API rather than divided here, so the card and the server cannot disagree about rounding) and the reset date (`next_usage_reset_at`). Derived: remaining, as `total_limit − current_usage`, two counts from the same response. Absent: **overage**. `FeatureUsageSummary` carries `is_soft_limit` but no overage figure, and the only overage anywhere in the SDK is the monetary commitment overage on `GET /subscriptions/usage`, keyed by meter and line item rather than by entitlement — a different concept, not a substitute. Units are absent too: the wire sends `unit_plural` but `TenantFeatureUsage` does not keep it, so the readings are bare counts rather than invented nouns. `OverageStaysADash` in the story is the regression guard.
- 2026-09-29 — flexprice/CustomerDetail: the Usage tab takes an optional `usage` ReactNode slot, rendering the customer's `QuotaCard` grid in place of the "No usage to show yet" empty state. A slot rather than a data prop because the quota read is its own endpoint with its own loading and failure states, and this component does not fetch; omitted, the section behaves exactly as before.
- 2026-09-29 — flexprice/charts: **new shared chart library** for the Overview and Revenue dashboards — `MetricChart` and `BlurredEmpty` in `charts.tsx`, plus `PillColumns` (`@reui/stats-14`), `HalfDonut` (`@reui/chart-12`), `SegmentMeter` (`@reui/chart-14`), `SplitMeter` (`@reui/chart-14` extended to several tones in one track) and `ArcGauge` (`@reui/chart-7`). `MetricChart` is **not** from a block: shadcn `Chart` (Recharts) under a stat-tab strip, after the Vercel console. The five block-derived ones are **composition, not `reui`** — each block exports a propless `Chart()` bound to its own `./data`, so they are adapted for their mark and geometry over real data, never mounted. `stats-14`, `chart-14` and `chart-7` installed under `components/blocks/**`; `styles.css` verified byte-identical across all three installs, and the primitives `--overwrite` rewrote (`avatar`, `tabs`, `button`, `card`, `tooltip`, `dropdown-menu`, `frame`) were restored — their only diff was a shuffled `"use client"`.
- 2026-09-29 — flexprice/charts — **no component in the library takes a colour.** They take a `ChartTone`, a closed union mapped to `--chart-1..5` and the status tokens in exactly one place, so a call site cannot express an unvalidated colour and the derived palette cannot drift. `series-1..5` are categorical, handed out in fixed order and **clamped rather than cycled** — cycling would give series 1 and 6 the same colour, which reads as "these are the same thing". `good`/`warning`/`critical` are reserved for state (`HalfDonut`'s paid/open/overdue, `ArcGauge`'s health) and are never in the categorical rotation. Trend deltas are `TrendBadge` (`success-light`/`destructive-light`), not coloured text — a tripwire story confirmed the a11y gate still fails `text-success` at 12px (3.67:1 light, threshold 4.5).
- 2026-09-29 — flexprice/charts: all seven are **presentational and fully controlled** — no fetching, and no `useState` for anything a page owns, so `MetricChart`'s active tab can live in the URL. Every multi-series mark carries a legend, so identity is never on colour alone; every mark carries a hover layer (a dashed crosshair on the line, a per-mark tooltip on the columns, arcs and meter tracks) whose triggers are **focusable buttons** carrying the exact reading as their accessible name, so the figure behind the approximation is reachable without a mouse. `BlurredEmpty`'s decorative chart is `aria-hidden` + `inert` + `pointer-events-none` — all three, since `aria-hidden` alone leaves a tabbable control a screen reader then refuses to describe. - 2026-09-29 — flexprice billing grids — **the rule the five were migrated under: a column shows a real value or an em dash, and a column no row can *ever* fill is removed rather than dashed.** An em dash says "this row has no value"; a permanently empty column says "these customers have no plan and no revenue", which is a different and much more damaging claim. Omitted on that rule, with the finding behind each: **MRR** (Customers, Subscriptions) — a case-insensitive sweep of `@flexprice/sdk` 2.1.30 for `mrr`/`arr` returns *nothing*, and `money.ts` forbids assembling one; **Plan / wallet balance / subscription count** (Customers) — `CustomerResponse` carries none of them and its own docstring says a customer has no plan; **Customer** (Payments) — `PaymentResponse` has no customer at all, not even a `customer_id`, only `destination_id` pointing at the invoice; **Applied to** (Taxes) — obtainable, but only by wiring `GET /taxes/associations`, which nothing calls yet.
- 2026-09-29 — flexprice/InvoiceGrid — **the redesign's tab list mixed two different statuses, so the grid now has two columns.** `Status` is what the document is (`invoice_status`), `Payment` is what the money did (`payment_status`); a finalized invoice nobody has billed and one whose only attempt failed are both `open` and differ only in the second column. The toolbar dropdown carries the domain's single folded `InvoiceStatus`. `paid` and `overdue` are **derived**, not stored — `isStoredInvoiceStatus` is false for both — so selecting either narrows the page already fetched, `InvoiceListPage` corrects `total` to match, and the grid renders a `role="status"` line above the toolbar saying so. An unfiltered ledger presented as a filtered one is the failure mode a billing console must not have.
- 2026-09-29 — flexprice/SubscriptionGrid — **"Past due" is not a subscription status and the option is dropped.** `SubscriptionStatus` is active / trialing / paused / cancelled / incomplete, on the wire as well as in the domain; past due is a property of an *invoice*. `Incomplete` — real, and previously unreachable from any control — takes its place. `Current period` renders as a range and needs both ends, which is why `currentPeriodStart` was added to the read model (below); one end alone is a renewal date wearing a period's label, so a subscription that has not started billing dashes instead.
- 2026-09-29 — flexprice billing grids — **no status dropdown in Billing carries a count, and that is the honest answer rather than a shortcut.** A count may only be the server's `pagination.total`. Customers, Payments and Tax rates all narrow status *client-side* (`POST /customers/search`, `GET /payments` and `GET /taxes/rates` have no status field), so no per-status server total exists; Subscriptions could get one the day `fetchSubscriptions` sends `SubscriptionFilter.subscription_status`; Invoices could count its four stored statuses but not `paid` or `overdue`, and a dropdown where four options carry a number and two do not reads as "there are no paid invoices". Either every option counts honestly or none shows a number.
- 2026-09-29 — flexprice/RevenueDashboard: **new `byCustomer` panel — "Revenue by customer", rendered as a named gap list rather than a grid.** An audit of `@flexprice/sdk` 2.1.30 found **no `POST /analytics/revenue` and no revenue-analytics resource of any kind**; the only two analytics routes are `POST /events/analytics`, whose `group_by` accepts `source`, `feature_id` and `properties.*` but never a customer, and `POST /costs/analytics`, which answers for the tenant or for one `external_customer_id` per request. The single per-customer revenue figure that exists anywhere — `total_revenue_amount` on `GET /customers/{id}/invoices/summary` — is a lifetime total, split per currency, one HTTP call per row, and unwired. So the panel names, column by column, the capability each would need. The surface this replaced listed five customers and their spend, and not one of those figures came from anywhere.
- 2026-09-29 — flexprice/RevenueDashboard — **the gross-margin sentence was factually wrong and is corrected.** It read "no endpoint returns the margin"; `POST /costs/analytics` (`client.costs.getDetailedCostAnalytics`) returns `total_revenue`, `total_cost`, `margin` and `margin_percent` outright.
